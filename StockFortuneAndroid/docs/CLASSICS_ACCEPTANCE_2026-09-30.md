## 二、必须修正的验收问题

### F1：两条原注的扫描页码与实际底本不符

| 条目 | 当前资产页码 | 实际扫描页码 | 核对位置 |
|---|---:|---:|---|
| `dtjy-v1-ji-annotation_excerpt` | 11 | **12** | 第12页右侧第一列起“己為田園之土…” |
| `dtjy-v1-xin-annotation_excerpt` | 12 | **13** | 第13页右侧第一列起“辛乃陰金…” |

对应资产：`app/src/main/assets/classics/ditiansui_jiyao.json` 第161、209行；固定选段：`tools/classics_selection.py` 第101、109行。

原因：抽取器 `split_sections()` 保存的是小节标题所在页，并把同一页码用于歌诀与原注。当前精校 Markdown 的分页并不总是保留原书段落的跨页位置。因此，MD/JSONL 互相一致以及重新抽取一致，仍然不能证明资产中的页码就是引文在 PDF 里的位置。己土的审计备注也已经写明“原注起于扫描页12”，但资产没有据此调整。

原计划里的页码表也沿用了该精校文本的小节页码，这是本次核图发现后需要更正的计划假设，不能将实现遵循原表本身归咎于实施者。

修正要求：区分“MD/JSONL 定位页码”和“对外展示的实际扫描页码”，己土原注显示12、辛金原注显示13；保留原切片编号的回溯关系。同步更新资产、固定清单、抽取器、审计报告和相关测试。跨页歌诀可记录起止页，至少不能把后一页开始的原注指到前一页。

### F2：底本回改条目绕过了默认门禁的全文校验

位置：`tools/verify_classics.py` 第101—103行。

当前逻辑只要条目在 `SCAN_RESTORE` 中登记，就允许 `original_text` 与选段清单不同，没有检查差异是否恰好等于登记的“合戊見火 → 合戊化火”替换。

独立复现：在临时 JSON 副本中把癸水歌诀改成“癸水這是一段偽造內容，合戊化火，火根乃真。”，保持其他字段不变。默认语料门禁仍返回 **exit code 0 / CLASSICS_OK**。该测试只操作临时副本，没有改动应用资产。

构建脚本调用的正是默认门禁；`--against-source` 能发现错误，但日常构建没有外部书籍目录，也不会执行这项检查。

修正要求：对每条选段生成唯一的预期入库文本，再将 `original_text` 与之完整比较。回改只能执行登记的、锚点唯一的一次替换，不能豁免整条文字校验。新增反例：正确回改通过；额外插字、删句、其他改字均失败。

### 附加发现：不支持的 schema 版本仍能通过

把 `_meta.schema_version` 从1改为999，默认门禁仍通过；C01只检查键存在，没有验证版本值。建议明确检查当前只接受 schema v1，并增加版本错误的反例。此项的复现结果也在 `validator-negative-probes.json`。
