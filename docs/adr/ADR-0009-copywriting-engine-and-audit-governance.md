# ADR-0009: 文案库解耦设计与文案审核产物接入治理准则

## 状态
**ACCEPTED**（2026-10-09）

## 背景
原始 V3 工作簿包含约 800 条（实测 765 条）待审判词，实测有约 40% 的条目包含合规禁词（如「忌」「收益」「机会」「避免」等），目前处于待人工终审状态，尚未完成合规改写。
在工程推进中，必须防范两类错误倾向：
1. 直接将未经审核的原始 V3 800 条粗暴塞入代码发布；
2. 为让测试通过而直接削弱或删除禁词门禁，或者伪造虚假的外部审核素材。

## 决策
1. **引擎接口与具体文案素材彻底解耦**：
   - Phase 4 与 Phase 5 优先建设结构化组合引擎（`FortuneCopyEngine`）和五段式解读数据模型（A.命理依据、B.本月主题、C.潜在矛盾、D.企业经营观察、E.综合解释）。
   - 规则库采用分层片段规范（结构键 $\rightarrow$ 合规短语），拒绝笛卡尔积穷举。
2. **测试期素材准则**：
   - 组合引擎使用已通过合规校验的既有 89 条片段以及受控模板进行验证与门禁测试。
   - 严禁擅自伪造未经审核的所谓「最终素材」。
3. **正式审核产物接入准则**：
   - 必须等待独立的文案人工终审与合规脱敏任务输出正式产物（审核后工作簿及哈希存档）。
   - 正式素材接入时必须执行自动化全量 60 禁词门禁与规则映射校验，任何违规条目立即拒绝合入。

## 后果
- 研发流程不因等待文案终审而完全停滞，可先行完成坚实的引擎与页面框架。
- 筑牢合规防火墙，杜绝任何未经审核的外部文案流入最终 Android 正式包。
